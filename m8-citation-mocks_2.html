Citation options

The native chip's look is Slack's to control. A and B are the two text fallbacks Block Kit supports when the native element isn't available — both are plain rich_text links. Hover any marker to see the preview card (tap on mobile); click opens the source in a new tab. Shown on all three so they compare like-for-like; note that only the native chip actually gets that card in Slack. Pill, circle-badge and icon chips were dropped: no inline styling exists for them.

Buildable: Unicode superscript digits (¹ ² ³) as rich_text link text. No hover preview; single digits only.

Buildable: "[1]" as a rich_text link — renders in Slack link blue and opens the source. No hover preview; works in plain mrkdwn too.

How Slack renders a citation natively

Slack's native citation element renders as one grey chip with three fixed parts. m8 supplies the data; Slack draws the chip and owns its behavior.

1Absence balance
1 · Number

The index — the citation's position in the answer. It ties the inline chip to the same row in the Sources footer, and shows how many sources back the answer.

Always shown · m8 sets the value
2 · Icon

Picked by Slack from the source type. For an outside system like Workday, m8 passes app_icon_url and Slack shows that logo; for Slack messages, files and web pages Slack uses its own glyph.

Slack-chosen · logo only via app_icon_url
3 · Label

The text field — a short source name. Keep it to two or three words; it is what makes the chip wide.

m8 sets the text
  • Hover (desktop) or tap (mobile) opens Slack's preview card: title, source, snippet, open link.
  • Click opens the record, message or file. Every chip is interactive — there is no static version.
  • Where it can sit: in a sentence, in a numbered Sources list, or at the end of a quoted excerpt (rich_text only).
  • When it appears: on the final message only — citations attach at chat.stopStream, not while text is streaming.
  • Not adjustable: shape, colour, size, or a custom icon. The chip looks the same as Slack AI's own citations.
  • If the native element isn't available: fall back to plain text markers — ¹ or [1] as links — with no preview.

Multiple citations

Two ways to present an answer that draws on several sources. Both keep one chip per claim in the text; they differ in how the sources are listed underneath. Every chip here is live: hover for the preview, click to open.

Option 1 — multiple chips

Each claim keeps its own inline chip, and a Sources footer lists all of them in citation order — each chip already carries its source icon, so no grouping is needed. The footer is sent in full; when the message runs long, Slack itself truncates it and adds its native Show more link — no button, no round-trip to m8. Slack chooses where the fold lands; here it's shown after the third source.

Rules of thumb

  • Dedupe by source, not by retrieved chunk; cap at 3–5 cited sources per answer.
  • One chip per claim, at the end of the sentence or clause — never a cluster.
  • Footer lists every source in citation order — no group headers, the chip icon says where it's from; long footers fold under Slack's native "Show more".
  • Citations attach on chat.stopStream only — streamed text has none, chips appear when the answer finalizes.
  • Never let the model produce URLs; inject verified source metadata after generation and validate every index maps to a real source.
